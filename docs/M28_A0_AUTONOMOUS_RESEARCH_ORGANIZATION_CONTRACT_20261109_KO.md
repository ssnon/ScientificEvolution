## 0. 이번 개발의 진짜 목적

만들려는 시스템은 연구자 둘을 만들어 경쟁시키거나, 정해진 횟수만큼 PEER → Population → Generation을 반복하는 시스템이 아니다. 주어진 과학 문제를 연구하기 위해 **누구/무엇이/어떤 관계로/언제까지 연구할지까지 과학적 근거로 결정하며 실제로 실행하는 범용 AI Scientist**다. 단일 연구, 동시 독립 연구, 재현·비판, 임시 협력, 통합, 분기, 지속, 합리적 보류·종결 모두 선택 가능한 수단이다. 어느 것도 의무 단계가 아니다.

이는 원래 비전과 현재 고정 orchestration 사이의 **설계 불일치**를 해결하려는 작업이다. M26 미완료의 원인이 이 불일치라는 증거는 아직 없으며, 동적 조직 기능 자체가 과학적 수행 능력 향상을 보장하지 않는다. 모델 능력, 연구 도구, 문제의 비식별성, 자료의 부재도 독립적인 후보로 남는다. 호출 수 절약은 목표나 성공 판정이 아니다.

## 1. 실제 코드에서 확인한 사실

| 영역 | 기존에 가능한 것 | 외부 실행기가 고정하는 것 또는 빠진 것 | 코드 위치 |
|---|---|---|---|
| 연구 행동 | Controller는 자유로운 Problem·Work 생성, `FRESH/DEVELOP/CHALLENGE/MUTATE/FUSE/DECOMPOSE/REFRAME/VERIFY` 선택, 기존 Work KEEP/DEFER/CANCEL/REACTIVATE 가능 | 새 독립 *연구 ROOT*를 생성하거나 ROOT 간 연구 조직을 구성하는 의사결정은 `controller_plan`의 현재 출력 계약에 없음 | `runtime/e2core/engine.py` `CONTROLLER_PROMPT`, `controller_plan` |
| 국소 연구의 지속 | `Engine.run`은 결과·Work 상태에 반응하여 Controller/Worker를 실행하고, `ONGOING` 상태의 Work를 계속 실행 | 최상위 persistent runner가 실행 시점에 미리 정한 세대/PEER 파동으로 감싸고 있음 | `runtime/e2core/engine.py` `_should_controller_run`, `run`; `persistent_population.py` `run` |
| 독립성 | `FRESH` Worker가 역사적 AI 정보를 받지 않도록 입력과 자산 계보를 제한; 외부 ROOT를 별도 생성할 수 있음 | 기존 PEER 생성은 `create_cycle(..., peer_count, ...)`가 운영 설정대로 수행; 연구자가 독립 연구 ROOT의 수·생성 시점을 직접 선택하지 못함 | `runtime/e2core/core.py`, `persistent_population.py` `create_cycle` |
| 결합 | `combine`은 여러 PEER 자산·미완료 상태를 provenance와 함께 통합 문맥으로 가져옴. 이후 Controller가 실제 `FUSE`를 거부할 수도 있음 | **강제되는 것은 과학적 FUSE 자체가 아니라** PEER 이후 COMBINE/POPULATION 단계라는 외부 일정 | `persistent_population.py` `combine`, `run` |
| 연구 보류·종결 | `HOLD_WITH_RATIONALE`, `SCOPED_NEGATIVE`, `REVIEW_WORTHY_CANDIDATE` 및 객관적 상태 평가가 이미 존재; 운영 예산 정지는 구분됨 | 국소 ROOT의 종료와 전체 연구 프로그램의 종료 및 조직 폐쇄가 동적 구조에서 어떻게 연결될지는 미정 | `engine.py` `controller_plan`, `run`; `core.py` `PROGRAM_OBJECTIVE_ASSESSED`; `persistent_population.py` `run` |
| 검증 | opt-in Native Math Cycle 및 실제 tool provenance와 분리된 모델 판단 존재 | 검증의 필요 여부·독립 검증자의 생성·종료를 일반적 동적 조직 의사결정으로 다루는 경로는 미완성 | `runtime/e2core/math_cycle.py` |

**중요한 구별:** 단일 ROOT 내부의 복수 Work는 이미 지원된다. `FUSE`도 자율적으로 선택할 수 있다. 그러므로 이를 처음부터 다시 구현하지 않는다. 부족한 것은 연구 프로그램 수준에서 **새로운 독립/정보공유 연구 단위의 실제 생성·연결·종료를 연구 판단과 연결하는 능력**이다. 특정 작업을 계속하기 위해 반드시 새 세대로 넘어갈 필요가 없도록 만드는 것도 포함한다.

## 2. 구현 방향: 고정 세대의 동적 파라미터화가 아니라 선택적 조직 변경

1. **기본은 현재 연구를 지속하는 것:** 이미 승인된 Work를 계속 실행할 수 있으면 별도의 연구자 생성·합성·세대 전환을 요구하지 않는다. `CONTINUE`를 매번 신규 유료 모델 판단으로 만들어야 한다는 뜻도 아니다.
2. **필요한 순간에 조직 변경:** 과학적 판단이 독립 연구, 재현, 별도 비판, 협업 또는 통합을 요구할 때만 실제 연구 단위를 만든다/연결한다. 연구자 수·역할·생성 시점·합성 시점은 고정되지 않는다.
3. **실행 가능한 제안만 인정:** '독립 연구가 필요하다'는 텍스트만 추가하는 것으로는 성공이 아니다. 검증 가능한 의사결정 원본, 새 ROOT 또는 Work의 실재, 도구/모델 실행·상태, 후속 연구에서의 정보 이용을 구분해서 기록해야 한다.
4. **기존 Controller를 첫 연결 지점으로 재사용하되 절대적인 메타 지도자로 고정하지 않는다:** 최초 구현에서 이미 존재하는 모델 판단 경로에 조직 변경의 선택을 허용할 수 있다. 장기적으로 연구자가 필요할 때 조직 변경을 제안하거나 위임하는 경로까지 확장 가능해야 한다. 별도의 상위 LLM Controller를 자동 추가하지 않는다.
5. **실험 실행 안전장치는 별개:** 외부 비용, 병렬성, wall time, 민감 자료, 네트워크·샌드박스 한도는 운영자 권한. 연구의 과학적 판단과 혼동하지 않는다.

## 3. A1에서 구현할 최소 *수직 통합* 기능

첫 개발 단위는 **'기존 연구 ROOT가 계속 실행되는 도중, 실제 과학적 판단에 의해 새로운 독립 ROOT 하나를 필요 시 생성하고, 그렇지 않으면 새 ROOT 없이 기존 Work를 계속하는 능력'**이다. 이 단위만으로 전체 AI Scientist 완성을 주장하지 않는다.

### 3.1 실제 실행 경로

- 새로운 연구 실험에만 선택적으로 meta-autonomy 계약을 활성화한다. 원래 M26 ROOT 또는 source-pinned 기존 실험을 변경하거나 새 계약에 따라 재해석하지 않는다.
- Controller가 일반 Work와 함께, 필요할 때만 **조직 변경 의도**를 표현할 수 있도록 한다. 연구자 수는 필수가 아니고 '조직 변경 없음'도 유효하다. 같은 Model 응답을 사용해 불필요한 별도 LLM 관리자 호출을 강제하지 않는다.
- 검증기가 의도를 **과학적 지시문(모델 작성)**과 **실행 허가/형식/독립성 조건(기계 검증)**으로 분리한다. 유효한 의도만 append-only Journal에 승인하고, 이미 저장된 요청/응답의 해시는 그대로 둔다.
- 외부 실행기가 승인된 의도에 따라 실제 연구 ROOT를 staging → 검증 → atomic publish 방식으로 준비한다. 반복 실행 또는 중간 실패 시 동일한 승인 ID의 중복 ROOT/중복 청구가 없어야 한다. 생성 결과와 원본 P0/source pin을 연구 조직 기록에 되돌려 남긴다.
- 실행기는 새 ROOT와 기존 Work를 **선택적으로** 진행시킬 수 있다. 고정 `PEERS → COMBINE → POPULATION` 단계는 이 경로의 필수 조건이 아니다. 자식 ROOT의 연구 결과는 명시적인 과학적 후속 선택 전에는 자동으로 '합성된 발견'이 되지 않는다.

### 3.2 FRESH의 실제 의미 — 두 경우를 구별

- `ORIGINAL_P0_BLIND_INDEPENDENT`: 선행 AI 연구자의 주장·가설·비판·사후 문맥으로 연구 질문 자체가 오염되지 않은 독립 연구. 중립적인 P0/허용된 일차 자료만 제공한다.
- `TARGETED_INDEPENDENT_CHALLENGE`: 기존 연구에서 선택한 특정 주장이나 대상을 겨냥한 독립 비판. 비판의 대상이 기존 AI 주장이라는 사실을 숨기지 않으며 *맹검 FRESH*라고 표시하지 않는다. 독립 검증의 자율성·출처는 별도로 기록한다.
- `INFORMED_CONTINUATION`: 이전 주장·계산·실패를 명시적으로 읽는 연구. 각 자료의 본래 provenance가 필요하다.

현재 `FRESH` 입력 필터만으로 최초 질문의 독립성이 저절로 보장되는 것은 아니다. 따라서 **선택 동기**와 **연구자에게 실제 전달한 문맥**을 각각 검증한다.

### 3.3 기록할 조직적 사실과 권한

- 과학적 제안: 왜 독립성/역할/협력/통합이 가치 있다고 판단했는가. 근거로 사용한 실제 자산·검증·실패·출처는 무엇인가.
- 명시적 승인: 어떤 연구 단위/Work를 생성·재사용·연결할 것인가. 중복 검사를 위한 안정적인 ID 및 원본 모델 판단 호출 ID.
- 실제 수행: 어느 ROOT가 생성됐는지, 어떤 원본 P0/초기 상태/자료에 접근했는지, 무슨 작업이 실행/미실행됐는지, 실패 시 그 이유는 무엇인지.
- 결과의 과학적 의미: 다른 연구자의 자료가 실질적으로 사용/거절/비판/보류됐는지. 단순한 자산 import는 합성의 성공이 아니다.
- 종료: 개별 연구자의 HOLD는 전역 P0 부정이 아니며, 운영 예산 일시정지는 과학적 종료가 아니다. 전역 종결은 포트폴리오와 미해결 가능성을 고려한 정당화가 필요하다.

**설계상 보류:** 새로운 event schema, 모델 출력 필드 이름, Journal의 전역/로컬 권한 경계, cross-ROOT 원자성 회복 프로토콜은 A1 코드 구현 직전에 최소 형태로 확정한다. 지금 하드코딩된 역할 목록·연구자 수·의무 호출 회수를 새 'AI Scientist 정책'으로 선언하지 않는다.

## 4. 설계 대안 비교 및 선택

| 대안 | 장점 | 핵심 위험 | A0 판단 |
|---|---|---|---|
| 기존 `persistent_population.run`에서 `peer_count`만 모델로 생성 | 변경량 작음 | 여전히 파동·합성·세대 단위를 기본으로 강제 | 목표 불충족: 채택하지 않음 |
| 모든 연구 결과를 새로운 상위 Meta-Controller에서 평가 | 관리 역할 분리 | 판단을 더 반복하고 실제 실행 능력과 분리될 수 있음 | 기본으로 채택하지 않음 |
| 기존 `Engine`/`Journal`의 연구 선택을 활용하고 조직 변경 실행 기능을 동적으로 연결 | 기존 실제 연구 기능 재사용; 필요 시 단일/다중/무합성 | ROOT 사이 무결성·독립성·복구 설계가 까다로움 | **A1 개발 방향** |
| 단일 장기 연구자에게 모든 결정을 위임 | 조직이 단순함 | 독립 비판·실제 다른 관점의 기회 제한 | 비교 기준으로만 유지; 최종 구조 확정 아님 |

이는 최종 아키텍처의 우월성을 입증한 것이 아니라, 사용자 목표에 **직접 불일치하는 필수 파동 가정**을 없애기 위한 최초의 구현 선택이다. 범용 AI Scientist는 다르게 구현할 수도 있다.

## 5. A1 no-paid E2E 수용 조건

아래는 강제 연구 절차가 아니라, 특정 조직 결정이 주어졌을 때 **실행기가 그 결정을 정확히 수행하는지**를 확인하는 개발 테스트다.

1. `NO_ORGANIZATION_CHANGE`: 하나의 ROOT에서 기존 Work가 계속되고, PEER·합성·세대 파일이 생성되지 않는다.
2. `INDEPENDENT_FORK_REQUESTED`: 실제 승인된 과학적 조직 의도 때문에 별도의 ROOT가 생성되고 원본 P0/문맥 격리를 검사한다.
3. `TARGETED_CHALLENGE`: 기존 주장에 대한 독립 비판은 *초기 P0 맹검 FRESH*로 허위 표시되지 않는다.
4. `PARALLEL_CONTINUATION`: 부모 Work가 ACTIVE인 동안 다른 연구 단위가 존재할 수 있고 자동 취소/완료되지 않는다.
5. `NO_FORCED_INTEGRATION`: 연구자가 요청하지 않으면 자산 통합·FUSE·다음 세대가 생성되지 않는다.
6. `EXPLICIT_SCIENTIFIC_HOLD`: 정당화된 국소/전역 과학적 HOLD와 운영 예산 중단을 구분한다.
7. `RETRY_AND_CRASH`: 모델 응답을 이미 저장했다면 재개 시 중복 호출·동일 조직 단위 중복 생성이 없고, 부분 실패는 과학적 성공/중단으로 오인되지 않는다.
8. `LEGACY_NO_REGRESSION`: 기존 M25/M26 원본 Journal·Source Pin 변경 없이 M16–M27 관련 지속성, FRESH·tool truth 회귀 통과.

엔지니어링 테스트는 '시스템이 이 선택을 허용할 수 있는가'를 입증할 뿐, '실제 모델이 적절한 선택을 하는가'를 입증하지 않는다. 특정 상황에서 AI가 반드시 연구자 두 명을 생성하거나 반드시 HOLD하도록 정답을 강제하는 테스트는 피한다.

## 6. 과학적 효과 평가 — 구현 뒤 별개로

- 동일 문제와 동일 자료에 대해 과학적으로 다른 연구 조직을 실제로 선택하는지 관찰한다. 변경이 없을 수도 있으며 그것도 정당화 대상이다.
- 새로운 연구자가 이전에 없던 수학적 반례, 계산 검증, 명확한 부정 결과, 새로운 일차 증거를 제공했는지 확인한다. 자산 수, 세대 수, 호출 수, JSON 성공률을 과학적 성과로 대체하지 않는다.
- 기존의 M26 특정 benchmark 미완료를 시스템 수준 실패로 단정하지 않으며, 과학적 정보 불충분 또는 구조적 비식별성의 가능성을 유지한다.
- 동적 조직을 사용한 경우와 현재 구조를 비교할 때는 운영 자원 조건을 맞춰 설명 가능성을 높이지만, **목표는 예산 최적화가 아니라 과학적 판단과 수행 능력**이다.
- 한 과학 분야에서 성공했다고 범용성을 선언하지 않는다. 적어도 성격이 다른 수학/계산/실험설계 유형의 열린 과제로 일반성 주장을 구분한다.

## 7. 개발 단계와 중단 조건

- **A0 (이번 문서):** 현재 가능한 능력과 확인된 조직 자율성 차이, A1 수직 통합 계약을 확정. 기존 감사 반복 없음. **완료 범위: 설계, 코드 동작 증거 확인; 구현 아님.**
- **A1:** 선택적 독립 ROOT 생성 + 부모 연구 지속 + 승인/실행 영수증 + 무강제 세대/합성. 가짜 모델을 사용한 오프라인 실세계 Journal 수직 통합 테스트.
- **A2:** 필요 시 자율적 협력/증거 통합/비판/포트폴리오 종료. 기존 `import_peer`·Math Cycle·자산 계보를 재사용하거나 명백한 한계가 있으면 재설계.
- **A3:** 재시작/동시성/오류복구/레거시 전체 회귀, 의도와 실행의 인과 연결 검증.
- **A4:** 유료 실제 연구 비교는 A1–A3 성공 후 독립 승인. 기존 SERS는 사례 중 하나이지 하드코딩 대상 아님.

**전환 또는 중단 조건:** A1 구현 도중 같은 가치를 더 적은 구조 변화로 구현할 수 있거나, 제안한 조직 원자성/독립성 계약이 모순된다는 사실이 밝혀지면 설계를 수정한다. 새 구조를 유지하기 위한 별도 기능 증식은 하지 않는다. 이행한 동작보다 문서상의 아키텍처를 우선하지 않는다.

## 8. 다음 코드 작업 지점 (A1)

- `runtime/e2core/engine.py`: 기존 Controller 결정과 조직 변경 의도의 연결, 기존 Work와 양립하는 opt-in 출력 계약 검증; 새로운 별도 LLM 관리자는 필요조건이 아님.
- `runtime/e2core/core.py`: 조직 결정/실행의 immutable provenance를 검증할 state/event 확장(새 ROOT만 opt-in).
- `AUTONOMOUS_SCIENTIFIC_EVOLUTION_20261029/persistent_population.py`: 고정 세대 실행 경로와 분리된 **선택적 조직 실행 경로**; 기존 세대/스냅샷 코드는 역사적 실험용으로 보존 가능하나 새 경로의 강제 단계로 사용하지 않음.
- `checks/m28`: 5절의 no-paid 수직 통합 테스트.

**확정하지 않은 것:** 새 프로그램 객체·상위 Controller·새 세대 정책·역할 taxonomy·검증 횟수 규칙·기본 연구자 수. A1의 우선순위는 새 객체의 개수가 아니라, *실제 연구자의 결정이 실제 연구 단위 생성/지속으로 이어지는가*다.
