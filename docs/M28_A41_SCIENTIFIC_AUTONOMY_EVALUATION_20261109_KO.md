## 0. 연구 목표 — 소프트웨어가 아니라 AI Scientist

**과학적 질문:** 과학적 문제 P0와 운영상 허용된 자원만 주었을 때, AI Scientist가 연구 문제·방법·조직·검증·연구 지속/종결을 근거에 따라 스스로 선택하고, 그것을 **실제 과학적 행위**로 연결하여 기존 주장에 의미 있는 변화를 만들 수 있는가?

M28-A4-0의 `A40_NO_PAID_CLI_JOURNAL_ENGINE_E2E_PASSED`는 두 ROOT, PRIMARY Controller 결정 5개, 자식 모의 Worker 자산 2개, 선택적 반입 1개, 부모 후속 모의 비판 자산 1개, 프로그램 판단 2개, 호출 비용 0이라는 **모의 종단 실행 결과**다. 과학적 성과 `NONE`; 실제 모델 판단 검증 `NOT_TESTED`. 메타 연구 자율성이라는 **선택지**의 구현은 실제 선택의 **품질**이나 **연구 수행 능력**의 증명이 아니다.

## 1. 무엇을 AI Scientist에게 맡길 것인가

인간이 정할 것: 원본 P0, 보안·도구 접근 허가, 총 지출/호출·병렬성·시간 등 **운영상 경계**, 사후 평가, 실제 실험/외부 공개 권한. 운영 한도가 소진돼도 과학적 `HOLD`로 분류하지 않는다.

AI Scientist가 결정할 것: 연구 전략, 특정 주장과 계산·증거 요구의 우선순위, 단일/복수 연구자, 독립 탐색/표적 비판/협력/통합/분기/연속 연구, 실패 후 재시도·방향 변경, 증거에 의한 `CONTINUE`·제한적 부정·`HOLD`·검토 가치 있는 후보. **원래 P0에 없는 하위 정답·정해진 연구자 수·고정 합성 횟수·필수 도구 호출 횟수를 유도하지 않는다.**

## 2. A4-1 최초 관찰 — 과학적 판단이 실제 연구에 이어지는가

- **P0:** 재현 가능한 기준선이 필요하면 기존 M26 선행 ROOT에서 `PROGRAM_CREATED.problem`을 **바이트 의미가 동일한 텍스트로 추출**하고 SHA256을 기록해 **새 별도 M28 실험**을 초기화한다. 보고서에 보존된 M26 P0 해시 `8fc9da6e2c3889ce7c379f6571912e33b8771d1fd1192a7c7dea8a037ac7e136`은 준비 단계에서 실제 원본과 일치 여부를 확인해야 한다. 원본 P0가 없으면 임의로 재구성하지 않는다.
- **초기 문맥:** 새로운 M28 ROOT는 기존 M26 AI 자산·가설·실행 기록을 자동 상속하지 않는 *새 연구*다. 따라서 M26과의 엄격한 성능 비교가 아니다. 연구 정보의 차이는 분석할 때 명시한다. **기존 M26 실험을 연장하는 것으로 표시하지 않는다.**
- **전제:** Source Pin, 연구자 독립성, 역사적 AI 출처 미검증 표시, 실행 Truth, UNCERTAIN 호출 처리, 개발 예산 경계를 실행 전 검사한다. `A4-0` 모의 검증은 이미 별도로 통과했다. 실제 M28 `run`은 내부적으로 `generational_run.drive(..., phase='syn')`를 호출하므로, **독립 ROOT 생성과 실제 Worker의 FRESH 입력 격리**를 혼동하지 않는다. 유료 실행 후 serialized Worker 요청에서 전달된 문맥을 확인한다. M25 `persistent_population.py`의 Activation Profile 강제가 이 별도 M28 실행 경로에도 자동 적용된다고 가정하지 않는다. 실행 전에 *실제 경로의* 활성 기능, 모델, 문맥/캐시 모드, 비용 승인·관측을 독립 확인한다.
- **실제 연구:** 사용자 별도 승인 뒤 한 번의 통합 연구 세그먼트를 실행한다. 연구자가 선택한 과학적 행동을 임의로 재배열하거나 인간이 '좋은 가설'을 끼워 넣지 않는다. 운영 한도는 미리 선언하고, `--paid` 및 `FAKG_RESEARCH_ALLOW_PAID=YES` 두 게이트를 만족시킨다. 유료 호출은 이번 무유료 준비 단계에 포함하지 않는다.
- **실행 관찰:** 원래 과학적 질문 → Controller 근거·조직 결정 → Work 선택 → 실제 계산/문헌 원문/증거 → 비판·수학 검증 → 수정된 주장/한계/다음 결정의 인과 계보를 *원본 Journal을 통해* 추적한다. 새로운 인식론적 진전이 없다면 `SCIENTIFIC_DELTA: NONE`을 그대로 기록한다.

## 3. 과학적 성과를 판단할 때 확인할 것 (사후 평가, 런타임 quota 아님)

| 질문 | 독립 감사의 근거 |
|---|---|
| 연구 전략은 정당했는가 | 근거 있는 선택·대안·가정·실행 가능성·예상 정보가치; 고정 Work/연구자 수로 채점하지 않음 |
| 실제 연구를 수행했는가 | 산술/수치 실행 원본과 재현성, 문헌 원문 접근 여부, 데이터·증거 등급, 계산 실패/`PLAN_ONLY` 포함 |
| 자기검증·자기수정이 있었는가 | 수정 전후 수학적 전제·값·증명/반례·검증기 결과·후속 의사결정 시간 순서 |
| 독립 연구가 실질적으로 기여했는가 | 이전에 없던 반례·제약·예측·강한 Null 또는 실제 결론 변경. 부모 링크/자산 import 자체는 성과 아님 |
| 결론/중단이 정당했는가 | 조건부 후보, scoped negative/비식별성, unresolved, HOLD, 운영상 pause를 분리하고 주장 범위를 평가 |
| 연구 조직의 자율성이 도움이 됐는가 | **실제로 선택한 조직**이 다른 연구 경로에서는 얻기 어려웠던 검증·행동을 낳았는지. 생성 수가 아니라 차별적 인과 기여 |

핵심 산출물은 **서로 추적 가능한 과학 주장 체인**이며, 후보가 없는 경우에도 왜 후보가 없는지에 대한 근거를 포함한다. 필요하면 사람이 별도로 계산·문헌을 재검증한다. 모델이 스스로 `LEVEL_II`라고 선언해도 독립 인증이 아니다.

## 4. 비교 설계의 엄격한 한계

이번 최초 M28 관찰은 M26의 미완료 원인을 단독으로 식별하지 않는다. M26은 기존 지식·Work 계보를 상속하고 192 SAVED 호출을 기록했다. M28 새 P0 단독 출발은 입력 정보와 실행 구조가 다르다. 동일한 P0라도 과거 자산·모델·도구·비용·실행 조건이 다른 결과를 **M28 구조의 인과적 성능 향상**으로 해석하지 않는다.

후속 대조는 목표와 초기 자료를 동일하게 고정한 병렬 시작 실험이 가능할 때 검토한다. 하나의 분야에서 성과가 있어도 범용성을 주장하지 않는다. 서로 다른 수학적 정식화/비식별성 문제, 계산 중심 문제, 문헌·실험 설계형 문제로 일반성을 분리해서 평가한다. 단순히 답을 맞히는 벤치마크가 아니라, 과학적 **전략-수행-비판-수정**을 볼 수 있어야 한다.

## 5. 준비 및 감사 계약

- 준비 패키지 `prepare_a41.py`: Source Pin 확인이 가능한 깨끗한 Git 코드 트리에서, 기존 P0 원문과 해시를 **read-only** 검사하고, 명시적 `--initialize`일 때만 **새** 실험을 `meta_research_autonomy.py init`으로 생성한 뒤 `preflight` 실행. P0 텍스트나 기존 Journal을 Git에 추가하지 않음.
- `inspect_a41.py`: 실제 실험 이후 원본 Journal을 읽기 전용으로 확인하고 운영·모델·조직·Work의 기본 현황을 JSON으로 요약. **과학적 진전 판정은 사람이 실제 주장 체인을 읽어 별도로 수행**한다.
- 유료 실행 명령은 `meta_research_autonomy.py run`에만 있다. **본 준비 패키지의 스크립트에는 유료 실행 경로가 없다.** 모델/예산/비용 승인 없이 실행하지 않는다.
- 기술적 중단·외부 호출의 불확정 비용·도구 부재는 과학적 부정/완료로 승격하지 않는다. 옛 Source-Pinned 실행은 변경 금지.

## 6. 중단·판단 기준

**과학적으로 유의미한 관찰**: 실제 실행된 검증 가능 계산/원문으로 제한된 주장 개선, 중요한 오류 수정, 정당한 반례, 정당한 식별성 한계 또는 근거 있는 연구 방향 전환/보류가 후속 판단에 영향을 줬다.

**연구는 수행했지만 결론 미완료**: 과학적 한계와 운영상 경계가 구분되고, 어떤 질문·검증·자료가 남았는지 구체적이다.

**실행 결함 확인**: 과학적 작업이 시작·계승·완료되지 않는 원인을 실제 Journal로 식별했다면 그 결함에 한정하여 수리한다. 새로운 정책·관리자·강제 세대를 기본값으로 추가하지 않는다.

**구조적 한계 확인**: 연구자가 필요로 한 과학적 조직·도구·판단 표현을 현재 M28이 지원하지 못했다면, 기존 구조를 지키기보다 기능적으로 더 적절한 구조로 재설계를 검토한다.
